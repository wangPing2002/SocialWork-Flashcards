# 社会工作闪卡 v3.0.0-rc1｜题库、案例与搜索整合工程

**本工程是可以直接导入 Android Studio / GitHub 仓库的源代码候选版，不是已经发布或经过 APK 真机验证的正式版。**以 `SocialWork-Flashcards(5).zip` 为只读母版，安全整合用户上传的 Z00—Z08 审校成果中能够确认字段和来源的内容。

## 功能

- **案例卡**：材料题优先展示可阅读的完整案例材料；进入案例主档后按第1问、第2问……独立作答。草稿在本机自动保存，参考答案手动揭晓，每问独立标记“本问掌握/仍需练习”；支持整案自测，提交后统一看解析。自编案例与汇编案例清晰区分，**不将任何一份未经核实的汇编材料宣传为官方真题**。
- **题型搜索**：卡片库保留文本及“全部/已学习/未学习/收藏”筛选，新加“全部题型/名词解释/简答题/论述题/案例分析题/材料题”6项单选过滤。文字搜索和题型过滤同时生效；无需输入关键词也可按题型浏览知识专题。
- **分组重构**：6个知识板块、22个一级专题、73个一级+二级组合；教材系统、专业方法、服务对象及服务场域分开。2497个 `C` 编号不变，学习记录仍以原编号为主键。新分类来源 `topic_taxonomy_v30.json`，旧 `cards.json` 原样保留。
- **题干与记忆**：经来源文件验证的训练题面写入 `question_overlay_v30.json`，不覆盖历史原题字段；Z06 的179条专业提示资源经答案 SHA 核对合入记忆层，Z05 中另外287条原字段匹配的提示修正合入（213条不匹配项保持原状）。全部正式答案保持原文不变。

## v3.0.0-rc1 案例材料深化（2026-10-22）

上一版的案例材料普遍较短。本版在**完全保留2497张原卡和正式答案**的前提下，进行了如下变更：

- **78份新编训练案例**：保存初版材料与SHA-256，补充具体人物、事件时间线、当事人对话、多方利益、已知/未知信息、机构约束、风险与支持资源；扩写材料直接用于案例阅读界面。当前扩写文本的长度为 **571—758 字符**，中位数约 **629 字符**，并不是以固定字数填充模板。
- **6份“汇编材料（原卷未核验）”**：历史收录原文逐字保留且默认显示，增加独立的虚构“补充训练情境”视图；切换时清楚提示**不属于原卷**。不把扩写伪装成校方真题，也不因阅读扩写就视为原卷完整。
- **2份公开权威案例机制启发的训练案例**：最高人民法院2023年反家庭暴力典型案例、最高检与中央社会工作部2025年未成年人检察社工典型案例；新编事件、人物与对话均不等于原公开案件事实。其出处链接可在App案例页查看，新增**6道训练子问及对应解析**。
- **原84份案例的176道小问和解析完整保留**；新合计**86份案例/182道子问**。案例切换不影响已保存的草稿与评级，原 C 编号不变。
- 展示“收录材料 / 原创训练扩展”的明确切换，来源与权威资料只作为参考，不用于宣称原卷完整。校方原题仍按计划书G2/G3独立核验。

核查报告见 `docs/case_enrichment_quality_report.md`，每个案例的原文哈希与扩写长度见 `docs/case_material_enrichment_manifest.json`，一键重复生成见 `python scripts/enrich_case_materials_v30.py`。**本交付未运行Android SDK或真机，不等于正式发布验收。**

## 安装与检查

1. 先保留用户原始 `SocialWork-Flashcards(5).zip`，**不要在原项目中覆盖 Z00—Z08 各自的 MainActivity.java**。独立解压本 ZIP 到 `D:\AndroidProjects\SocialWork-Flashcards` 等无中文路径下；若已有项目，请先使用独立 ZIP/Git 备份，再完整替换工程源码，不覆盖手机内学习记录。
2. Windows PowerShell：`python scripts/verify_repository.py`；`python scripts/verify_v30_integrated.py`。两个脚本应全部 PASS。
3. 在 GitHub 新分支上传工程，触发 Actions 工作流 `Build Android APK`；下载调试 APK 在 Android 设备检查卡片库题型过滤、案例材料长滚动、逐问草稿、自评与返回路径。**本交付未实际运行 SDK 编译、模拟器或真机。**
4. 如需回退，使用原始 ZIP 或 Git 分支恢复；导入新版本前应先通过 App“我的 → 导出备份”保存既有用户学习记录。**绝不使用 Gradle 备份。**

## 版本号与升级兼容

- 现行正式版为 `v2.9.0`，下一正式版本目标为 **`v3.0.0`**。该工程为 **`3.0.0-rc1`（待验收候选版）**，不能称为正式发布；通过最终验收后，将 `app/build.gradle` 的 `versionName` 修改为 `3.0.0` 才可创建对应发布标签。
- 候选 `versionCode` 为 `27`，高于当前正式 `v2.9.0` 的 `25`；正式版本需保证 versionCode 不下降，并延用正式版签名。
- 设置页版本号直接读取 `BuildConfig.VERSION_NAME`，避免页面仍显示旧版 `v2.9.0`。
- 旧 RC 内部曾使用 `case_v31_drafts` / `case_v31_ratings` 作为用户草稿与评级存储键；为防止升级后既有数据丢失，此处**保持存储键不变**，不代表 App 正式版本是 v3.1。
- 原 Z00—Z08 分包内部的历史命名和校核路径仅属于工作批次，不代表发布版本。`main` 分支、签名密钥和已发布 `v2.9.0` 不受影响。
