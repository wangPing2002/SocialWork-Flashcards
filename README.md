# 1. 项目简介

“社会工作闪卡”不是把大段答案简单搬进手机，而是围绕主动回忆建立完整学习闭环：

> **学习 → 主动回忆 → 揭晓答案 → 熟悉度判断 → 间隔复习 → 弱卡优先 → 内容纠错 → 题库修订**

项目主要面向社会工作考研复习，同时兼顾日常知识整理与碎片化复习。

### 核心特点

- Android 原生离线应用；
- 不需要账号，学习数据默认保存在本机；
- 每日学习量统一管理；
- 支持未完成会话继续学习；
- 复习只从已经学习过的卡片中产生；
- 最近 10 次学习结果参与弱卡排序和熟练度判定；
- 长答案、例子、真题信息按需展开；
- 支持模糊搜索、多关键词和有限同义词映射；
- 支持收藏、本地修正、内容反馈；
- 支持完整备份与恢复；
- 正式版使用固定 Release 签名，支持长期覆盖升级。

- 调整主色、背景色与弱化色，减少高饱和元素，长时间复习更耐看；

- 首页继续将“今日任务”作为唯一主学习入口，统计信息改为更紧凑的分块展示；
- 学习页缩短题目上方无效留白，保留“主动回忆 → 查看答案 → 熟悉度评价”的固定学习流程；
- “我的”页面增加当前版本卡片，明确显示 V2.9.0 与题库规模。

## 2.2 冷启动与运行流畅度优化

- 约 9.3 MB 的 `cards.json` 不再阻塞 UI 主线程：启动时先显示加载页，再在后台完成题库解析；
- `quick_memory.json` 与教材框架数据在启动后台预载，减少第一次切换“快速记忆”时的卡顿；
- `CardRepository.byId()` 从逐卡线性查找改为 HashMap 索引；
- SQLite 本地修正与完整答案覆盖增加内存缓存，避免启动、搜索和列表渲染中反复查询数据库；
- 学习状态增加内存缓存，避免统计、专题进度和组卷时反复解析 SharedPreferences JSON；
- 卡片库搜索增加 180ms 输入防抖，避免每输入一个字符立即执行完整扫描；
- 专题卡片列表改为每次最多渲染 60 张并按需继续加载，降低一次性创建大量 View 的内存压力。

## 2.3 快速记忆与数据兼容

- “完整解答 ⇄ 快速记忆”的选择现在写入本地设置，跨卡片、跨学习会话仍保持用户上一次选择；

- 完整备份与内容反馈导出中的应用版本已同步更新为 `2.9.0`。

## 2.4 稳定性与兼容性

- 保留原有异常退出堆栈记录与“稳定性诊断”；
- 启动异常改为独立错误页，可直接重新加载，避免只显示不可操作的纯文本错误；

# 4. 学习与复习机制

## 4.1 每日学习量统一

项目不再把“每日新学量”和“每日复习量”拆成两个设置，统一为：

> **每日学习量**

例如设置为 30 张：

- 当天未完成目标时，系统生成剩余学习队列；
- 当天目标完成后仍可继续加练；
- “继续学习”从上次中断位置恢复，不重新抽卡。

## 4.2 学习与复习边界

严格遵守：

> **复习只能从已经学习过的卡片中产生。**

未学习卡不会被当作“复习卡”。

已经学习的卡可以：

- 重复出现；
- 根据薄弱程度增加出现概率；
- 在达到复习时机后优先进入队列。

## 4.3 最近 10 次与弱卡优先

每张卡保存最近 10 次评价：

- 熟悉；
- 不清楚。

排序综合考虑：

1. 是否已经学习；
2. 是否达到复习时间；
3. 最近 10 次“不清楚”比例；
4. 最近连续“不清楚”次数；
5. 距离复习到期时间。

目标行为：

- 一般卡通常出现 1 次；
- 中度薄弱卡可重复约 2 次；
- 高度薄弱卡可重复约 3 次；
- 尽量避免同一卡片连续出现。

## 4.4 间隔复习

基础间隔参考：

```text
10 分钟 → 30 分钟 → 12 小时 → 1 天 → 2 天 → 4 天
→ 7 天 → 15 天 → 30 天 → 60 天
```

实际优先级还会结合最近 10 次表现，因此不是机械按固定时间排序。

## 5.1 当前规模

当前安装包内包含：

```text

5 类正式题型：名词解释 / 简答题 / 论述题 / 案例分析题 / 材料题
逐卡完整标准答案
逐卡预测考频、真题标注、来源、答案状态与关联问题
```

主要覆盖：

- 社会工作原理；
- 社会工作实务；
- 个案工作；
- 小组工作；
- 社区工作；
- 社会工作督导与服务管理；
- 医务、学校、司法、防灾等实务领域；
- 企业社会工作；
- 基层治理；
- 退役军人事务社会工作；
- 新就业群体社会工作；
- 社会心理视角、诊断学派等理论内容。

## 5.2 资料使用原则

### 答案内容优先级（2026-10 调整）

**先检索《王思斌〈社会工作概论〉（第 4 版）笔记和课后习题（含考研真题）详解》272 页，再使用教材补足或核对。** 对每一道卡片，按以下顺序处理：

1. **《详解》“考研真题与典型题详解”优先**：先核查是否有同一题目或题意、考查范围、题型基本一致的题。优先吸收该题的定义、核心分点、论证次序和答题层次。区分有明确高校年份的真题与未注明来源的典型题，不混淆真题身份。
2. **《详解》“课后习题详解”次之**：没有合适的考研真题解析时，优先查找同题或实质等价的课后习题参考答案；“复习笔记”和知识框架仅辅助定位、查漏与理解，不替代完整作答。
3. **四份指定核心教材用于核验和补强**：上述详解没有对应答案、覆盖不足、存在知识错误或与题意不符时，使用《社会工作概论》《社会工作实务-250纠正》及 2026 年人大版《社会工作综合能力（中级）》上下两部分，补齐概念、机制、步骤、实务技巧和必要案例；对重要冲突回到教材核验，不把辅导书当作高于教材的事实权威。
4. **东南大学真题与《东南大学——院校分析与真题解读》PPT负责校准**：前者限定本校实际命题要求、考查角度和真题标记；后者校准名词解释的“范畴—定义—多维补充”、简答/论述的“总—分—总”、论证逻辑、得分点突出和案例表达。PPT 的答题模板不是新的事实性知识来源。
5. **其他参考答案仅作兜底补充**：当《详解》和四份核心教材仍不足以回答时，才参考已提供的其他真题解析与高分答案，提取有依据的补充得分点；不得无证据拼接、虚构内容或改变原题范围。

**“优先参考”不等于“逐字照搬”。** 对已完成的 2497 张卡先匹配，再逐卡比较；原答案已完整且与《详解》一致的保留，缺项才增补，结构不佳才重组。原题只问一个维度时，不能因为《详解》有完整大题就扩写到偏题。

### 第七轮新增：简答题“先释义、后分点”的答题校准

依据《东南大学——院校分析与真题解读》PPT 第12、15—17页，简答题采用**总—分—总**：第一段先明确题干涉及的关键专业术语，再引出所问维度；中段按一级得分点清晰展开；结尾用简洁的意义、评价或实务联系收束。PPT是答题结构参照，**不是事实来源**。

- **首段专业定义**：针对题干实际提问，交代所属领域、概念内涵，以及有依据的主体、对象、手段、目标等要素。不得以“这一问题十分重要”“包括以下几个方面”“需要结合本章”充当定义。
- **比较题**：先分别解释两个（或多个）核心概念，再从题目要求的相同维度比较，避免只定义其中一项。
- **原理/方法题**：简述模式、机制、原则时，首段界定该模式/机制/原则的独特含义，而不是仅复述“社会工作是专业助人活动”。
- **实务技巧题**：根据材料或题目界定所用介入模式，再结合对象与情境写明行动主体、具体方法、操作步骤和可观察结果；不以通用术语代替真实措施。若资料不足，不凭经验拼凑新的技巧。
- **分点与总结**：一级得分点以最具辨识度的核心判断为中心，保留完整论证和自然段；结尾不重复其他题目的通用空话。保留高亮 `#C62828` 的既定规范。
- **来源冲突时**：优先参照王思斌272页详解中实质对应的真题/习题组织得分点，以核心教材核实概念与细节；不能直接对应时不得强行改写。区分“来源直接对应”“源书同一概念”“仅原答案结构优化”。

**重要区分：**“答题首段应有概念解释”不等于所有题目都要塞入同一套社会工作定义。案例和材料分析题允许先概括情境核心矛盾，再结合适用专业概念展开。

### 统一答案规范（继续有效）

- 名词解释以 250—300 字、简答以 500—700 字、论述/案例约 900 字为目标，保证自然段结构、总—分—总和完整论证；字数服从题目实际要求，不机械凑字。
- **仅核心结论和真正得分句用 `#C62828` 高亮**，展开解释、机制、例子和过渡文字使用普通颜色；不恢复“30 秒口述版”。
- 每张修订卡标明具体参考：如“《详解》第 X 章 §X.3，第 Y 页”，并区分“直接匹配、同义匹配、教材补强、参考答案兜底”；保留可追溯的核心教材依据。
- 修改 `fullAnswer` 时同步检查关键词/得分点、`sourceField`/`origin`、真题证据与问题范围；母版与 `cards.json` 必须同步，不能单独覆盖 App 资源造成内容漂移。
- 不因在《详解》中出现相近题就擅自新增本校真题标签；真题年份、学校、科目应以明确证据为准。

资料发生冲突时，不静默拼接成一个“看似完整”的答案；明确记录差异并回到核心教材核验，仍无法确认则暂缓内容替换。

> 本节是**后续内容复核/改写规则**。修改规则本身不表示 2497 张现有卡片已按新顺序重新核对或更新，实际修改须有逐卡核验记录。

## 5.3 正式卡片最低标准

正式卡片应满足：

- 问法自然，接近教材习题或真实考试；
- 核心答案能够被来源支持；
- 例子不改变理论边界；
- 扩展理解不伪装成教材原文；
- 真题年份、科目、题型不猜测；
- OCR 不清、来源不完整的内容不作为确定事实发布。

## 5.4 真题发布规则

真题信息区遵循：

- 只有年份明确、题干明确、专题对应明确的记录进入主考频；
- 2024 / 2025 等仅依据汇编顺序推定年份的记录单独标注，不计入主考频；
- “未发现直接命题”不等于“低频”或“不重要”；
- 未通过核验的真题显示“答案待核验”；
- 不用相关专题的泛化答案冒充某一道具体真题的答案。

App 支持在不修改正式题库文件的情况下保存本地修正。

## 6.1 内容反馈

可标记：

- 概念或答案错误；
- 答案不完整；
- 题目表述不准确；
- 真题信息有误；
- 出处 / 章节有误；
- 例子或扩展答案有误；
- 知识点重复或冲突；
- 其他。

## 6.2 本地修正

可修改：

- 题目；
- 答案要点；
- 记忆提示；
- 出处；
- 例子；
- 名词解释完整答案；
- 简答完整答案；
- 论述 / 案例完整答案。

本地覆盖保存在：

```text
content_feedback.db
```

不会直接修改安装包内的：

```text
cards.json
details.json
```

## 6.3 反馈闭环

标准修订流程：

1. 在 App 中标记或本地修正；
2. 导出内容反馈 JSON；
3. 上传反馈文件；
4. 回到教材 / 真题重新核验；
5. 更新正式题库；
6. 在 README 版本记录中注明修订；
7. 发布下一版本。

核心原则：

> **宁可少一张卡，也不要多一张不可靠的卡。**

# 12. README 维护规则

`README.md` 是项目唯一的主要说明文档。

以后**不要再新增**：

```text
CHANGELOG_Vx.x.md
CONTENT_ACCURACY_NEW.md
RELEASE_SIGNING_NEW.md
PROJECT_STRUCTURE_NEW.md
NEW_CARDS_xxx.md
```

新版本发布时：

1. 更新 README 顶部版本号与项目状态；
2. 如果功能 / 数据 / 签名 / 内容规范发生变化，同步修改对应正式章节；
3. 在“版本更新记录”中追加该版本；
4. 保留旧版本记录，不重复在 README 开头堆放版本说明。

目标是：

> **README 顶部永远描述当前真实状态，底部版本记录负责保存历史。**
