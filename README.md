## V2.4.5：模糊搜索与相关度排序优化

本版本继续优化卡片库检索体验，不修改题库正文、考频真题数据和学习算法。

- 搜索支持多关键词，使用空格分隔，例如“危机 介入 原则”；
- 多关键词采用 AND 逻辑，所有关键词都需要在同一卡片的不同字段中找到，减少无关结果；
- 支持部分词匹配，例如“社会支”可匹配“社会支持理论”；
- 增加少量经过人工限定的社工专业同义词映射，例如“赋能↔增权”“危机干预↔危机介入”“临终关怀↔安宁疗护”“REBT↔理性情绪治疗”“韧性↔抗逆力”；
- 搜索范围覆盖题目、知识点、卡片类型、答案要点、记忆提示、出处、例子及完整答案；
- 搜索结果按相关度排序：题目命中优先，其次知识点、答案要点、扩展答案等；
- 搜索结果显示主要命中来源，如“匹配：题目 / 知识点 / 答案要点”；
- 在题目和知识点行中高亮命中的关键词；
- “全部 / 已学习 / 未学习 / 收藏”筛选继续可与搜索叠加；
- 不做激进的错别字猜测，避免考研题库出现过度召回和错误关联。

## V2.4.4：卡片库搜索增强 + 冗余学习量模块精简

本版本继续聚焦日常使用效率，不改动题库正文与学习算法。

- 移除“卡片库”顶部重复的“今日学习量 / 继续学习”大模块，让卡片库回归查找与管理；
- 移除“统计”页顶部重复的“今日学习量 / 今日完成 / 连续学习 / 继续学习”模块，进入统计页后直接展示学习趋势与掌握分布；
- 将卡片搜索提升到卡片库首要操作位置；
- 搜索不再只筛选专题，而是直接返回具体卡片；
- 支持检索题目、知识点、卡片类型、记忆提示、出处、答案要点及扩展答案；
- 搜索结果显示题目、所属知识点、卡片类型、学习状态和收藏状态；
- 点击搜索结果进入该卡片的管理页，再进入学习/复习，手机返回仍回到卡片库；
- “全部 / 已学习 / 未学习 / 收藏”筛选可与搜索同时使用；
- 增加搜索结果数量和一键清除搜索词；
- 首页的每日学习量仍保留，因为它承担开始学习、继续学习和每日任务入口；本次仅移除卡片库与统计页的两个重复模块。

## V2.4.3：真题答案入口 + 返回栈 + 系统安全区优化

本版本继续优化学习过程中的“上下文连续性”，并为部分高置信度真题增加可核验参考答案入口。

- `考频与真题`中的每道真题改为独立信息卡；通过核验门槛的题目显示 `查看已核验答案` 按钮；
- 真题答案不宣称为东南大学官方标准答案，界面统一标注“已核验参考答案（非官方标准答案）”；
- 只有“年份明确 + 题干明确 + 与已核验专题答案直接对应”的真题才开放答案按钮；年份推定、回忆摘要或题干与通用专题答案不完全对应的记录继续显示 `答案待核验`；
- 首批开放 38 条已核验真题参考答案，其余 165 条继续保留真题记录但不生成泛化答案；
- `危机介入原则`按“及时处理、限定目标、输入希望、提供支持、恢复自尊、培养自主能力”六项原则单独校准；
- `社会工作督导的基本原则与功能`单独按原则 + 行政/教育/支持三大功能重构，不用通用专题答案替代；
- 相关知识点点击后先在当前学习页弹出就地预览，不再默认跳离学习流程；
- 如主动点击“进入专题”，手机返回键会返回原来的记忆卡，并保留当前卡、答案展开状态和答案标签；
- 学习页按返回键回首页但保留未完成会话；专题详情返回卡片库；卡片库/统计/我的返回首页，避免一次返回直接退出 App；
- 针对 Android 15 / targetSdk 35 的 edge-to-edge 行为增加 `WindowInsets` 安全区处理，顶部标题、状态栏/刘海、底部导航不再重叠；
- 题库 `cards.json` / `details.json` 不改动，学习记录、收藏、本地修正和内容反馈完全兼容。

### V2.4.3 真题答案发布门槛

1. 不把“相关知识点的通用答案”冒充某一道真题的答案；

6. 后续扩充优先提升准确覆盖率，而不是追求一次性给 203 道题全部生成答案。

## V2.4.2：学习页纯回忆 + 真题考频 + 知识点关联

本版本重点优化“先回忆、再反馈”的学习闭环，并增加可核验的考试信息。

- 问题页进入纯回忆状态：只显示题目与“点击显示答案”，不提前出现“不清楚 / 熟悉”，也不显示例子、完整答案、历史等提示性工具；
- 点击显示答案后，才出现“不清楚 / 熟悉”评价按钮；只有评价后才计入本次学习并进入下一张；
- 答案页增加三个切换标签：`核心答案 / 考频与真题 / 相关知识点`；
- `考频与真题`严格依据《东南大学社会工作考研真题2015—2026》：主考频只统计“直接命中本专题且年份明确”的题目；2024/2025回忆截图的年份按汇编顺序推定，单独展示且不计入主考频；
- 对真题汇编中缺失、模糊或未完整记录的题目不猜测、不补造；
- `相关知识点`只链接当前题库中真实存在的专题，分为“本卡关键关联 / 延伸知识点”，用于构建理论—方法—实务知识网络，不计入考频；
- 固定卡片框与内部滚动继续保留；收藏、本地修正、内容反馈、完整备份继续兼容；
- 修复 V2.4.1 中 `CardRepository` 重建时未捕获受检异常导致 Release 编译失败的问题；
- `applicationId` 仍为 `com.seu.socialworkcards`，用户学习记录与收藏数据保持兼容。

### V2.4.2 真题数据准确性规则

1. “高频/中频/低频”仅按年份明确的直接命题年份数计算：3 年及以上为高频，2 年为中频，1 年为低频；
2. 2022 回忆摘要因年份和考点明确，可列入年份明确记录，但界面保留“回忆摘要”来源标签；
3. 2024/2025 图片未在题面正文直接显示年份，因此界面标为“顺序推定”，不进入主考频；
4. 2026 图片明确写有“26原理/26实务”，按明确年份展示，但来源仍标为回忆截图；
5. 只有与专题直接对应的题目进入本专题考频；案例中仅可能用到某理论的，不因“可用”而计入直接考频；
6. 真题文字以用户提供的真题汇编为依据，OCR 不清处不自行补写。

本阶段**不直接覆盖正式 `cards.json` / `details.json`**。原因是此前用户在实际使用中发现较多内容问题，因此从 V2.3 开始执行“先审查、再替换”的内容发布流程。

本阶段已完成：

- 对现有 **490 张卡片 / 95 个专题**建立审查基线；
- 将《东南大学社会工作考研真题2015—2026》中的题目按“年份—科目—题型—知识点”建立映射；
- 重点使用王思斌《社会工作概论》（第4版）配套资料中的**课后习题、考研真题、典型题和答案结构**来判断题型、考点和答题框架，而不是机械复制其所有内容；
- 对 2022 等回忆版真题标注较低置信度；
- 对真题文件第 20—25 页的图片型资料，凡原图没有年份标题的内容均标注“按文件顺序推定”，不把推定年份当作绝对事实；
- 2026 实务图中“3 道名词解释”只能清楚辨认“社会观护、预估”两项，第三项不猜、不补；
- 建立外部核验登记表，优先采用 IFSW、NASW、University of Kansas、NCBI/学术资料等权威来源核对概念边界；
- 新增 `content/content_map_v2_3.json`，作为下一步重建正式题库的机器可读依据。

### V2.3 内容发布硬规则

1. 真题资料主要决定“考什么、怎么问、什么最重要”；
2. 王思斌资料主要决定教材框架、典型题型和答案组织方式；
3. 卡片答案不能只因为“看起来合理”就进入正式库；
4. 每张正式卡至少要有教材/可靠专业资料支持；核心概念再做独立文献交叉核验；
5. 来源间存在差异时，以东南大学备考口径和指定教材表述为主，同时避免把争议观点写成唯一事实；
6. OCR、回忆版或截图不清楚的内容不自动纠正、不猜测；
7. “真题卡”必须保存年份、科目、题型和来源置信度；
8. 正式替换前必须先通过内容审查，优先保证准确性，不追求卡片数量。

# 1. 项目定位

“社会工作闪卡”是一款用于社会工作考研复习的 Android 闪卡应用。

核心目标不是把大段答案简单搬进手机，而是建立：

**学习 → 主动回忆 → 熟悉/不清楚判断 → 间隔复习 → 弱卡优先 → 内容纠错 → 正式题库修订**

的完整学习闭环。

主要特点：

- Android 原生离线应用；
- 不需要账号；
- 学习数据默认只保存在本机；
- 支持每日学习量；
- 支持继续学习；
- 复习内容只来自已经学习过的卡片；
- 支持重复复习；
- 最近 10 次学习结果参与排序；
- 多次“不清楚”的卡片会更频繁出现；
- 例子、完整答案按需展开；
- 支持本地修改卡片内容；
- 支持标记内容错误并导出反馈；
- 支持完整学习数据备份与恢复。

# 3. 核心学习逻辑

## 3.1 每日学习量统一

不再区分：

- 每日复习量
- 每日新学量

统一为：

**每日学习量**

例如设置为 30 张：

- 当天尚有学习额度时，“开始学习”会生成当天剩余数量的智能队列；
- 当天目标完成后，可以继续加练；
- “继续学习”不会重新抽卡，而是从上次中断的位置继续。

## 3.2 学习与复习的边界

严格遵守：

> **复习只能从已经学习过的卡片中产生。**

未学习卡不会被系统作为“复习卡”抽取。

已学习卡可以：

- 重复复习；
- 多次进入学习队列；
- 根据薄弱程度提高出现频率。

## 3.3 固定卡片尺寸

主卡片区域保持固定尺寸，避免：

- 翻答案后页面突然变高；
- 不同卡片尺寸频繁变化；
- 长答案破坏记忆节奏。

较长内容使用：

- 卡片内部滚动；
- “例子”按钮；
- “完整答案”按钮。

# 5. 智能复习规则

每张卡保存最近 **10 次**：

- 熟悉
- 不清楚

排序综合考虑：

1. 是否已经学习；
2. 是否达到间隔复习时间；
3. 最近 10 次“不清楚”的比例；
4. 最近连续“不清楚”的次数；
5. 距离复习到期时间。

## 5.1 弱卡优先

多次“不清楚”的卡片：

- 会更早进入队列；
- 会获得更高抽取权重；
- 在一次学习任务中允许重复出现。

当前设计目标：

- 一般卡：通常 1 次；
- 中度薄弱卡：可出现约 2 次；
- 高度薄弱卡：可出现约 3 次；
- 避免同一张卡连续出现。

## 5.2 间隔复习

总体采用基于遗忘规律的间隔设计。

曾使用的基础间隔：

`10分钟 → 30分钟 → 12小时 → 1天 → 2天 → 4天 → 7天 → 15天 → 30天 → 60天`

实际优先级还会叠加最近 10 次表现，因此并非机械按固定时间排序。

# 6. 内容纠错与本地修正

从 **V2.1** 起加入内容纠错系统。

## 6.1 标记“内容有误”

学习页可以直接标记：

- 答案内容有误
- 题目表述有误
- 出处/章节有误
- 例子或扩展答案有误
- 知识点重复或冲突
- 其他

同时可以填写备注。

例如：

> “教材第十章这里应为过程目标，不是结果目标。”

## 6.2 本地修正

用户可以直接修改：

- 题目
- 答案要点
- 记忆提示
- 出处
- 例子
- 名词解释完整答案
- 简答完整答案
- 论述/案例完整答案

## 6.3 本地数据库

内容修正与反馈保存在：

`content_feedback.db`

本地修改不会直接覆盖：

- `cards.json`
- `details.json`

这样可以保留：

**原始正式题库 + 用户本地修正版**

两层数据。

## 6.4 导出反馈 JSON

可以导出：

- `reports`
- `cardOverrides`
- `detailOverrides`

将 JSON 上传给 ChatGPT 后，可以：

1. 找到具体问题卡；
2. 查看用户备注；
3. 回到教材/真题重新核验；
4. 修改正式题库；
5. 在后续版本中合并。

> ChatGPT 无法自动读取手机私有数据库。必须由用户主动导出并上传反馈文件。

# 8. 内容准确性规范

从 V2.1 起，新增与修订闪卡统一遵守以下标准。

## 8.1 资料优先级

优先级从高到低：

1. 指定教材、用户上传教材原文与明确标注内容；
2. 东南大学历年真题及用户提供的真题资料；
3. 用户提供的高分答案、章节讲义与备忘录；
4. 只有用户明确要求“补充、验证、扩展”时，才使用外部资料或模型知识。

如果来源冲突：

- 不擅自揉成一个答案；
- 优先保留教材主口径；
- 必要时明确标注冲突。

## 8.2 每张正式闪卡最低要求

必须具备：

- 正式、自然的真题/教材习题式问法；
- 可核对的知识来源或章节；
- 核心答案要点能够被来源支持；
- 例子不能改变理论边界；
- 扩展理解不得伪装成教材原文；
- 无法确认的年份、题型、出处不得猜测。

## 8.3 四道检查

### A. 术语检查

核对：

- 名称
- 人物
- 年份
- 理论归属
- 阶段
- 模式
- 原则

不得随意混淆相近概念。

### B. 问题检查

题目要像：

- 真题
- 教材习题
- 正式考试问法

禁止使用内部提示式问题。

### C. 答案检查

短卡要求：

- 碎片化；
- 简短；
- 完整；
- 按重要性排序。

长答案要求：

- 总—分—总；
- 分点互不重复；
- 不为了凑内容添加来源未支持的细节。

### D. 来源检查

- 出处放答案/详情页；
- 正面题目不显示出处；
- 真题年份、科目、题型只有资料确认后才写；
- 无法确认时写“教材相关章节”或“当前资料未确认”。

## 8.4 用户反馈闭环

正式修订流程：

1. 用户在 App 中标记错误；
2. 导出反馈 JSON；
3. 上传给 ChatGPT；
4. 回到教材/真题核验；
5. 修改 `cards.json` / `details.json`；
6. 在 README 更新记录中写明修订；
7. 发布新 APK；
8. 无法确认的争议项保留“待核实”。

核心原则：

> 宁可少一张卡，也不要多一张不可靠的卡。  
> 宁可明确“资料不足”，也不要用看似完整的内容填补证据空白。

# 10. 固定 Release 签名

从 V2.2 开始，正式发布统一使用同一份 Release keystore。

只要：

- applicationId 不变；
- Release keystore 不变；
- versionCode 递增；
- 正常覆盖安装；

后续版本就可以保留已有用户数据。

## 10.1 创建 keystore

只创建一次。

Windows PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\create-release-keystore.ps1
```

脚本会生成：

```text
socialwork-release.keystore
socialwork-release.keystore.base64.txt
```

### 极其重要

`socialwork-release.keystore` 必须永久保存。

不要：

- 上传公开 GitHub；
- 删除；
- 每个版本重新生成。

如果丢失，未来将无法用同一签名覆盖升级已经安装的正式版本。

## 10.2 GitHub Secrets

GitHub 仓库：

`Settings → Secrets and variables → Actions → New repository secret`

添加：

```text
ANDROID_KEYSTORE_BASE64
ANDROID_KEYSTORE_PASSWORD
ANDROID_KEY_ALIAS
ANDROID_KEY_PASSWORD
```

## 10.3 发布 Release APK

例如：

```powershell
git tag v2.2.0
git push origin v2.2.0
```

GitHub Actions 的 Release workflow 会生成签名 Release APK。

未来：

```text
V2.2
↓
V2.3
↓
V2.4
↓
V3.0
```

必须始终使用同一份 keystore。

## 10.4 从旧 Debug APK 迁移

旧的 GitHub Runner Debug APK 可能使用不同 debug 签名。

因此，如果：

- 手机上已有旧 debug APK；
- 新 Release APK 提示签名冲突；

Android 无法直接覆盖。

切换正式 Release 前建议：

1. 先在旧 App 中导出全部学习数据；
2. 保存备份文件；
3. 再进行正式 Release 版本迁移；
4. 安装后导入备份恢复数据。

一旦完成固定 Release 签名迁移，之后就可正常覆盖更新。

# 14. 后续版本文档规则

从现在开始，**README.md 是项目唯一的主要说明文档**。

以后例如发布：

```text
V2.3.0
V2.4.0
V3.0.0
```

不再新增：

```text
CHANGELOG_V2.3.md
CHANGELOG_V2.4.md
RELEASE_SIGNING_NEW.md
CONTENT_ACCURACY_NEW.md
NEW_CARDS_xxx.md
```

而是直接在 README 的：

```text
# 13. 版本更新记录
```

下面追加：

```markdown
## V2.3.0

### 新增功能
- ...

### 内容修订
- ...

### 数据库变更
- ...

### 题库新增
- ...

### Bug 修复
- ...
```

如果某项规范发生变化，例如：

- 签名规则
- 内容准确性标准
- 数据库结构
- 题库组织方式

则同时修改 README 对应的正式章节，并在版本更新记录中写明变化。

这样可以保证：

> **README 始终代表项目当前真实状态，版本记录则保留历史变化。**
